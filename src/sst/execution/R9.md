The validated build also includes main's frozen R11 changes and Pauli's frozen

## Ownership and interfaces

| Owner | Private state and operations | Value boundary |
|---|---|---|
| `AnalogController` | Analog device/backend and shared analog bridge; request tickets/tokens; deferred fused submission; acceptance/completion; wake generation, tick, servicing flag and last device cycle; operation/word counters | `executeCpuAnalog`, `startDeferredAnalogLoadLookahead`, `deferredMatches`, `validateInitialCpuDevice`, `serviceAnalogBridge`, `onWake`; `Statistics` returned by value |
| `MemoryAccessController` | Physical request metadata/IDs, blocking request and step, group ID set, RAW hazards, store buffer and group/request counters; R5b SPM step/deadline; sole owned SPM timing model | `executeCpuMemory`, `onResponse(id)`, `reserveCPU`, `reserveDMA`, scalar status and value statistics |
| `GlobalDMAClient` | Execution/token completion table, iteration/flag validation, physical submission/completion counters, local tick and SPM-cycle deadlines, wait-delay state, scalar/batch retirement | `executeCpuGlobalDMA`, `onCompletion(GlobalDMAMessage)`, `drained`, value `Statistics` |
| `InitializationBarrierClient` | Initialization phase, aggregate accounting/delay/arrival/release; epoch order, arrival/release flags/counters, prefix release decision and exit validation | `start`, typed initialization/barrier actions, typed releases, `validateExit`, value `Snapshot`; prefix result requests Tile lifecycle teardown |

`cpuActions.h` is independent of SST and the CPU controller. Device adapters
consume typed action fields directly: there are no reconstructed QemuSyncEvent
envelopes or single-case switches in their execution methods. Transport protocol
enums/value messages are independent of SST; the existing SST event envelopes
retain their serialization and wire fields.

There is no Tile pointer, Tile friend, mutable collection accessor, or callback
borrowing a replay queue. Pending-event callbacks return metadata values from
`CpuExecutionController::pending()`; action payloads are independent values, not
aliases into the CPU replay tape. Memory group completion is identity-qualified
and occurs only when its physical ID set is empty. A later ack for a released
buffered store can retry a subsequent step, not retire it.

### One SPM and task context

Construction creates one `ScratchpadTimingModel`, wires its existing scheduling
service to RX/TX, then transfers ownership into MemoryAccess. MemoryAccess is
declared before RX/TX, so their resource borrows also remain valid during member
destruction. CPU replay reservations and globalDMA reservations use MemoryAccess
methods; no getter exports the owned model or its calendars. RX/TX implementations
and the timing-model implementation are unchanged.

MemoryAccess obtains `{taskId, executionId, phase}` by value from a Tile callback
when issuing each physical request and preserves that attribution through its
response. R10 can replace that lambda with a conversion from `TaskTrace.context()`.
Tile's report/progress/task ownership and legacy positional writer calls are
deliberately retained for main's subsequent R10 integration. The staged TaskTrace
and writer sources were not edited by R9. `Makefile.am` includes the new owners,
protocol headers and Pauli's `measurementWriter.cc/.h` and `summarySnapshot.h`.
Main owns the matching `run-test.sh` writer dependency update.

## Behavior and lifetime

- R5b `cpuExecutionController.cc` is byte-identical to the accepted baseline:
  instruction eligibility ticks, wake generations and early-completion guards
  are unchanged. MemoryAccess retains the direct SPM step/deadline checks.
- globalDMA retains tick/cycle conversion, remote completion plus local deadline
  requirements, latest-deadline batch retirement, and teardown exclusion from
  physical counters. No scheduling flag is treated as proof of elapsed time.
- RX service precedes TX service, which precedes analog bridge service. RX
  invalidation responses are still routed before ordinary memory responses;
  authorized invalidations release RX waits before TX waits. Analog wakes retain
  CLOCKPRIORITY, generation equality and exact-tick checks. CPU wake event types
  and priorities are unchanged.
- Immediate buffered stores preserve the historical internally-complete but
  externally-blocked watchdog observation through `reportBlockedAfterCompletion`.
- `UniqueFileDescriptor` owns the parent's globalRAM duplicate and closes it on
  unwind/destruction, replacement, and normal startup handoff. It never owns the
  deployment's original backing descriptor. The actual duplicate is acquired
  during setup; RAII also covers general constructor/member unwinding.
- Tile's destructor stops/drains CPU capture before terminating QEMU. CPU is the
  last declared member, so it is destroyed before all borrowed endpoints even
  if construction unwinds. Existing finish/emergency reporting order is retained;
  both stop/drain capture before closing any bridge mapping. Deferred ready-set
  callbacks retain R8's revocable lease checks before accessing owners.

The lifecycle contract remains simulator-owner-thread teardown, not arbitrary
concurrent cancellation or rollback. The test suite reruns R8's runtime/initial/
local capture cancellation and post-destruction callback tests, plus new fd
constructor-unwind/move/reset tests. It does not exhaustively inject live-QEMU
crashes at every SST shutdown point. Invalid device operations retain their
existing rejection policies; this extraction does not promise transactional
rollback of every invalid input.
