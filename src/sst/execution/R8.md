# R8 execution ownership and verification

Implemented against the completed R7/R5a state. Reference installation:
`build/src2/baselines/r7-r5a-1788560931812394855/install`.
All paths below are relative to the repository root.

## Owners and interfaces

- `CpuExecutionLedger` owns grant context, cumulative grant baselines, open
  issue-region occupancy and cumulative instruction/vector/cycle totals.
  It has no SST, device, transport or logging dependency. `accountTo` independently
  checks monotonic counters, `V <= I`, and `deltaV <= deltaI`; epoch and grant
  budget validation belongs to `validateCaptured`. Preview operates on a copy.
- `CpuExecutionController` owns pending CPU events, every replay envelope and
  record collection, record/group cursors, macro endpoint order, grant/resume
  transitions, initial/runtime pending capture flags, local lookahead future and
  identity, CPU wake/watchdog state, armed guest waits and execution statistics.
  `pending()` copies scalar metadata field by field; it never copies replay
  vectors. Statistics and accounting are returned by value. Tile has none of
  these mutable execution queues or state fields.
- `QemuCaptureCoordinator` owns initial partition registries, runtime ready-set
  queues/frontiers, bounded executors, local lookahead scheduling and capture
  statistics. Workers receive transport values and cancellation leases. Owner
  callbacks validate, preview and commit in the existing deterministic order.
  Tile retains only SST event representation/priority, dispatch and wiring.

Typed `CpuMemoryAction`, `CpuAnalogAction`, `CpuNetworkAction`,
`CpuGlobalDMAAction`, `CpuBarrierAction`, `CpuInitializationAction`, and
`CpuTaskAction` callbacks return `CpuDeviceResult`. Completion and a scheduled
delay are mutually exclusive. A callback returns completion; it cannot also
reenter `completeDevice`/`completeMemory`. Both reject stale or repeated step IDs.
Each pending replay endpoint has a new internal step ID even when several
endpoints share one bridge event sequence.

Tile's temporary R9 adapters retain analog acceptance/queues, global-DMA tokens
and deadlines, initialization/barrier state, and physical memory request IDs,
hazards and store-buffer occupancy. They do not access replay records by
reference or mutate a replay cursor. A memory action carries only its dispatched
group as a value. Group completion reaches execution only after the physical
request-ID set drains. Blocking stores retain the step ID of the current blocked
request; an older buffered-store response can retry readiness, not retire a
newer event using its old ID. Analog callbacks retain the existing event/token
readiness and generation checks before completing the current CPU step.

There is no Tile pointer/reference or friendship in either execution owner.
Narrow callbacks supply resources/results without exposing Tile's fields.

## Accounting and ordering preserved

For total instructions `I` (including vectors), vector instructions `V`, and
issue width `W`, a complete issue region costs `max(ceil(I/W), V)`. Charges are
differences of this cumulative occupancy. A new grant clears grant-local
baselines while preserving issue occupancy. Architectural endpoints clear
occupancy after charging. Equal counters, including vector-memory fragments,
add no instruction charge.

| Replay endpoint | Final-segment policy |
|---|---|
| Memory / analog records | Charge each selected architectural endpoint and close its region. |
| Memory / analog envelope | Charge through the envelope; close only for fused non-quantum terminals. |
| DMA-submit envelope, including fused wait | Charge the tail without closing the region. |
| DMA macro delimiter | Schedule zero cycles; retain the last wait's baseline. The next captured event charges delimiter instructions. |
| Ordinary-memory group | Charge its head, dispatch the group, then advance past the group only on completion. Remaining deltas are charged at the next selected endpoint/tail. |

Scratchpad replay retains one owner-thread reservation loop and aggregate wake,
using the shared SPM arbiter. CPU issue totals exclude device service and waits.
Ready-set preview retains the original unsplit envelope estimate, including its
ordering role; it is not replaced with a replay/device simulation.

RX-before-TX-before-analog service order and RX's ability to release a TX wait
remain intact. The immediate buffered-store path explicitly reports its original
blocked outcome to the enclosing wake handler after advancing execution, keeping
the old watchdog observation/cancellation sites. R5a's typed local-DMA deadline
calculation and unconditional not-yet-at-deadline guards remain in the device
adapter. No old untyped DMA timing expression was restored.

## Lifetime and invalid-input behavior

`stop()` revokes the capture lease, removes queued runtime captures, cancels and
drains an incomplete initial partition, waits for local capture, then clears
execution work. Cancelling an initial participant revokes that partition's
participants before waiting, so another initial worker cannot keep using an
endpoint being destroyed. Already-collected commit callbacks check their lease
before dereferencing their owner and become harmless after revocation. Validation
and preview callbacks on a revoked endpoint fail collection.

Tile calls stop before bridge closure and from its destructor while resources
are still alive. Worker transport capture polls its lease and bridge at bounded
wait intervals. Normal ready-set collection joins worker results before returning
owner callbacks. These APIs require the SST owner thread; cross-thread simulator
cancellation and execution rollback are not introduced or claimed. Host tests
cover queued runtime cancellation, incomplete initial cancellation, active local
capture cancellation and a collected callback invoked after owner destruction.
They do not inject every possible live-QEMU/OS failure.

Two explicit invalid-input corrections accompany extraction: cumulative ledger
overflow and inconsistent vector deltas now throw before committing any ledger
state. The previous unsigned-total wrap is not retained. This changes invalid
input handling only; the hardware comparisons below establish valid-run timing
and counter agreement. A disabled-launch lifecycle fixture also initializes its
CPU clock converter before constructing the new owner.

## R9 handoff

Extract the existing typed Tile device adapters with their physical state into
their R9 owners. Keep the callback/result and step-completion contracts, shared
SPM arbiter, RX/TX wake ordering, and global-DMA deadlines. Execution replay state
does not need another move. Transport batching counters retain their existing
definitions (including macro endpoint counts); measurement redesign remains R10.
Host wall time and compiler/model-suite performance are outside these hardware
equivalence gates.
