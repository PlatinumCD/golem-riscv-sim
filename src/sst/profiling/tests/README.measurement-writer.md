# R10 measurement writer integration

`PerformanceProfile::writeSummary(const SummarySnapshot&)` is now the sole
summary API; the temporary 45-argument overload has been removed and both test
callers migrated. It delegates to the same file writer: no duplicated CSV
formatting. Tile, Makefile, installed binary and existing test runners are
untouched by this change; main owns their post-R9 integration/build wiring.
Resource controllers retain counter ownership. `SummarySnapshot` is a caller-
assembled value; `MeasurementWriter` only validates/renders/writes files.

## Isolated host tests

From the repository root (C++17; no SST build, installation or simulation):

```sh

  -Ithird_party/sst-core/external \

g++ -std=c++17 -Wall -Wextra -Werror \
  -DMITTENS_SOURCE_TREE='"src2"' \

  src2/sst/profiling/measurementWriter.cc \
  -o "$r10_test_dir/performance-profile-test"
"$r10_test_dir/performance-profile-test"
```

The tests independently parse JSON using the already-vendored nlohmann header
(test-only dependency). The named profile API and standalone writer compare the
complete CSV byte-for-byte against `expected_summary_csv.h`, an independent
golden captured from the old writer before integration. They then compare every
ordered available JSON metric to every CSV
field. Coverage includes duplicate normalized stop names, unchanged wait names,
64-bit integer extremes, missing/disabled/not-measured versus measured zero,
unknown/not-measured legacy payloads, JSON escaping including control bytes and UTF-8,
nonclassic global locale, clock factors, compiled/unknown provenance, environment
spoof resistance, TX conservation (all three histograms independently, deficit,
excess, overflow, zero/max windows, missing arrays), profile/writer completion
validation, writer diagnostics availability, and validation before output mutation. Evidence directories
are printed and retained in `/tmp`.

## Integration handoff after R9 / coordinated build

1. The named profile API delegates to `MeasurementWriter` with actual writer-owned
   diagnostics. Clock regressions are not-measured when tracing is off; counters
   of written progress snapshots remain available. No counters are collected here.
2. The positional adapter is removed. The named API checks available completion/
   submission values before writing, and tests check both global DMA and analog
   rejection. Stop/wait order and duplicates remain preserved. The independent
   golden still pins the pre-migration CSV, not output generated by this writer.
3. Main assembles the primary snapshot from controller snapshots. Integer assignment
   means available, even for zero. Use `disabled()` for absent hardware,
   `notMeasured()` for instantiated but uncollected metrics, and default construction
   for unknown availability. Never infer availability from a numeric zero.
   `notMeasured(legacyValue)` now preserves the supplied CSV payload while JSON
   remains null/not-measured. Use it for main's planned T2/T4 legacy blocked
   metrics, not an available zero. `disabled()` keeps the zero CSV fallback.
4. Add the new files to build/distribution wiring and the tests to the appropriate
   host runner. Any target linking `performanceProfile.cc` now also needs
   `measurementWriter.cc`. These wiring changes belong to main, not this patch.
5. Populate actual SST timebase, resolved ticks-per-domain-cycle factors, resolved
   configuration reference and run/build manifest reference. Compile definitions
   supply default source tree and implementation ID; absent definitions produce
   explicit unknown. No environment-derived identity is used. The implementation
   ID is not claimed to be an installed-binary hash.

## Schema 1 and limitations

Files: `tile-N-summary.csv` (legacy rows/order) and `tile-N-summary.json`.
JSON has schema `mittens.summary`, integer `schema_version: 1`, provenance,
timebase, contract reference and an ordered `metrics` array. The array intentionally
preserves duplicates. Every metric has `name`, `value`, `status`, `unit`, `domain`,
`aggregation`, and `known_scope`. Unavailable values are JSON null. CSV alone has
no availability channel and retains zero or explicit legacy compatibility payloads.
Consumers must use JSON availability, not interpret those CSV fallbacks as data.

JSON integers are exact uint64 decimal literals; consumers using IEEE-754 numbers
must use a lossless integer parser. Metadata text is expected to be UTF-8. JSON
escapes quotes, backslashes and all ASCII control characters. CSV reason names
remain tokens: commas, quotes, CR/LF and NUL are rejected, not silently rewritten.
Metadata permits those characters and round-trips them through JSON escaping.

Semantics follow `../MEASUREMENT_CONTRACT.md`. No derived busy union, true bank-
delay duration, corrected TX observation or new NIC/router statistics are invented.
The legacy analog-active field is the device's `elapsedCycles()`, not an array
compute-service sum. RX DMA service is CPU-domain despite the separate RX engine
clock. Shared SPM service already includes TX/RX contributions. Network summary
packet/word totals are TX-only; transit time is RX-side and not pure wire latency.

Both outputs are rendered and validated before opening files, and write failures
are reported. The pair is not an atomic transaction; the run manifest remains
responsible for artifact completeness. This foundation does not change snapshot
observation sites, model state, or existing CSV formats/trace writers. Full R10 completion
still depends on post-R9 integration and the coordinated equivalence gate.

`SummarySnapshot::transmitObservations` now emits a JSON-only `tx_observations`
object: `observedCycles` and optional `readyCycles`, `activeCycles`,
`directionCycles` arrays. Copy from TxController counters as follows:

| Snapshot member | TX counter |
|---|---|
| `observedCycles` | `transmitOpportunityObservedCycles` |
| `readyCycles` | `transmitReadyCycles` |
| `activeCycles` | `transmitActiveLaneCycles` |
| `directionCycles` | `transmitReadyDirectionCycles` |

All arrays have five entries for 0, 1, 2, 3, 4-or-more (the controller saturates
the last bucket). A supplied array requires an available window and an exact,
overflow-safe sum equal to that window. Missing arrays are unknown unless the
window explicitly says disabled/not-measured, in which case they inherit that
status. Zero window plus zero buckets is explicitly measured, not missing.
Units are CPU cycles and aggregation is previous-observed-state duration, not
event-complete activity or true busy time. Directions count ready-burst first-hop
diversity (queued and assigned), not active router cardinal links. No missing
bucket is inferred and the writer never invokes the controller's observer.
